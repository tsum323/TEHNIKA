# Админ-панель

Внутренняя программа для владельца и сотрудников: заявки, клиенты, техника, поставщики,
закупочные цены, наценка, выручка, прибыль и статистика.

**С публичным сайтом не связана**: отдельное приложение в папке `admin/` со своими зависимостями.
Сайт не может случайно показать закупочные цены — у него нет к ним доступа.

Адрес после публикации: `https://<владелец>.github.io/<репозиторий>/admin/`
(для этого репозитория — https://tsum323.github.io/TEHNIKA/admin/). В меню сайта ссылки нет,
поисковики страницу не индексируют.

## Что умеет

| Раздел | Что внутри |
| --- | --- |
| Обзор | Новые заявки, заявки в работе, выручка, прибыль и наценка за месяц, последние заявки |
| Заявки | Все обращения, фильтр по статусу, поиск. В заявке — клиент, техника, даты, цена. Владелец видит блок «Финансы»: поставщик, закупочная цена, доп. расходы и сразу — выручка, расходы, прибыль, наценка |
| Техника | Цена для клиента; у владельца — у каких поставщиков есть, почём берём, разница за смену и наценка |
| Поставщики | Контакты и условия; у владельца — какая техника у поставщика и сколько ему заплатили |
| Клиенты | База клиентов и история их заявок |
| Статистика | За месяц / 3 / 12 месяцев / всё время: выручка, расходы, прибыль, наценка, маржа, средний чек, доля выполненных заявок, графики по месяцам, прибыль по технике и категориям, источники заявок |
| Сотрудники | Только владелец: включить или отключить доступ, назначить роль |

### Роли

- **Владелец** — видит и меняет всё.
- **Менеджер** — заявки, клиенты, техника, поставщики. **Не видит** закупочные цены, расходы, прибыль
  и раздел «Сотрудники», не может удалять записи.

Ограничения работают **в самой базе данных** (Row Level Security), а не только в интерфейсе:
даже если менеджер попробует запросить закупочные цены напрямую, база вернёт пустой ответ.
Новый пользователь создаётся **без доступа**, пока владелец его не включит.

### Как считаются деньги

- Выручка = цена для клиента за смену × смены
- Расходы = закупочная цена за смену × смены + доп. расходы (доставка и т. п.)
- Прибыль = выручка − расходы
- Наценка = прибыль ÷ расходы (на сколько процентов продаём дороже, чем берём)
- Маржа = прибыль ÷ выручка (какая доля выручки остаётся нам)

В статистике деньги считаются только по заявкам со статусом **«Выполнена»**.

## Демо-режим

Пока база не подключена, админ-панель работает на **выдуманных данных** (они сбрасываются при обновлении
страницы). Вверху — переключатель «Смотреть как: Владелец / Менеджер», чтобы увидеть разницу в правах.
Как только в GitHub появятся секреты базы (см. ниже), панель автоматически начнёт работать с настоящими данными.

## Подключение базы Supabase (один раз, можно с iPad)

Supabase — облачная база данных с бесплатным тарифом. Все шаги делаются в Safari.

1. **Создайте проект.** Зайдите на https://supabase.com → Start your project → войдите (например, через GitHub)
   → New project. Укажите название (например, `tehnika-admin`), придумайте и **сохраните** пароль базы,
   регион — ближайший к вам (например, Central EU). Нажмите Create new project и подождите пару минут.
2. **Создайте таблицы.** В проекте откройте **SQL Editor** → New query. Откройте в GitHub файл
   [`admin/supabase/schema.sql`](supabase/schema.sql) → кнопка «Copy raw file» → вставьте в редактор → **Run**.
   Должно появиться «Success. No rows returned».
3. **Запретите самостоятельную регистрацию.** Authentication → Sign In / Providers → выключите
   «Allow new users to sign up» → Save. (Даже если забыть, новые пользователи всё равно без доступа.)
4. **Создайте себя.** Authentication → Users → Add user → Create new user: ваша почта и пароль,
   включите «Auto Confirm User» → Create user.
5. **Сделайте себя владельцем.** SQL Editor → New query → вставьте содержимое
   [`admin/supabase/make-owner.sql`](supabase/make-owner.sql), замените `ВАШ_EMAIL@example.com` на свою почту → Run.
6. **Скопируйте адрес и ключ.** Кнопка **Connect** вверху проекта (или Project Settings → API Keys):
   - Project URL — вида `https://xxxx.supabase.co`;
   - **Publishable key** (`sb_publishable_…`) или, в старых проектах, **anon public** key.
   Этот ключ публичный: без входа по паролю он ничего не открывает.
   **Никогда не используйте `service_role` / secret key** — он обходит всю защиту.
7. **Добавьте их в GitHub.** Репозиторий → Settings → Secrets and variables → Actions → New repository secret:
   - `SUPABASE_URL` — Project URL;
   - `SUPABASE_ANON_KEY` — publishable (anon) key.
8. **Опубликуйте.** Actions → «Публикация на GitHub Pages» → Run workflow (или просто слейте любой PR).
   Через 2–3 минуты откройте `/admin/` — появится экран входа.

### Сотрудники

Supabase → Authentication → Users → Add user (почта, пароль, Auto Confirm). Затем в админ-панели
раздел «Сотрудники» → «Включить доступ». По умолчанию роль — менеджер.

### Резервные копии

На бесплатном тарифе Supabase хранит данные надёжно, но автоматических резервных копий нет.
Раз в месяц делайте выгрузку: Table Editor → нужная таблица → Export → CSV.
Неактивные бесплатные проекты Supabase ставит на паузу примерно через неделю без запросов —
её можно снять кнопкой Restore в панели Supabase; данные при этом сохраняются.

## Для разработки

```bash
cd admin
npm install
npm run dev        # http://localhost:3001 (без .env.local — демо-режим)
npm run check      # линтер + типы + сборка
```

Схема базы — `supabase/schema.sql` (повторный запуск безопасен), типы таблиц — `src/types/db.ts`.
При изменении схемы обновляйте оба файла.
