# Правила проекта

Сайт компании по аренде строительной техники в Краснодарском крае.
Стиль — Industrial Premium: графит, сталь, сигнальный жёлтый, строгая сетка.

@AGENTS.md

## Технологии

- Next.js (App Router), TypeScript, Tailwind CSS, ESLint.
- Строгая проверка типов TypeScript обязательна (`strict: true`). Не используем `any` без крайней необходимости.
- Сайт публикуется как статический (`output: "export"`) на GitHub Pages в подпапке репозитория.
  Нельзя использовать возможности, требующие работающего Node.js-сервера: Server Actions,
  API-маршруты с запросами, cookies, headers, redirects, rewrites, ISR, middleware/proxy.
- Пути к файлам из `public/` оборачиваем в `asset()` из `src/lib/paths.ts` (учитывает basePath).
  Внутренние ссылки — через `next/link` или `ButtonLink`.
- Анимации — только CSS-переходы. Библиотеки анимаций не подключаем. Учитываем `prefers-reduced-motion`.
- Новые зависимости добавляем только при реальной необходимости.

## Где что лежит

- Временные тексты, контакты, категории, техника и цены — `src/content/`.
  В начале каждого такого файла комментарий «ВРЕМЕННЫЕ ДАННЫЕ — заменить на реальные».
- Типы данных — `src/types/`.
- SVG-заглушки — `public/placeholders/`.
- Дизайн-токены (цвета, шрифты, радиусы) — `src/app/globals.css`, блок `@theme`.
- Базовые компоненты — `src/components/ui/`, шапка и подвал — `src/components/layout/`,
  секции главной — `src/components/sections/`.
- Тексты и контакты не вписываем прямо в компоненты, если их можно взять из `src/content/`.

## Безопасность данных

- Запрещено хранить секреты, пароли и токены в исходном коде. Файлы `.env*` не коммитим (кроме `.env.example`).
- Закупочные цены, данные поставщиков и внутреннюю экономику сделок запрещено помещать
  в публичные данные (`src/content/`, `public/`) и в клиентский код. Всё, что попадает в сборку, видит любой посетитель.
- Не придумываем реальные реквизиты, отзывы, рейтинги, сертификаты, гарантии и достижения компании.

## Порядок работы

- Каждое новое задание выполняется в отдельной ветке (`feature/NN-короткое-название`) и завершается Pull Request в `main`.
- Не работаем напрямую в `main`. Слияние Pull Request выполняет владелец проекта.
- Перед Pull Request обязательно: `npm run lint`, `npm run typecheck`, `npm run build` — все без ошибок.
- После каждого задания — отчёт на русском языке: что сделано, какие проверки выполнены и с каким результатом, что не проверено.
- Не выполнять задачи, не входящие в текущее задание.
