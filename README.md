# TEHNIKA — сайт аренды строительной техники

Сайт компании по аренде строительной техники в Краснодарском крае.
Сейчас это **первая версия**: главная страница, дизайн-система и служебная страница `/ui`.
Все тексты, контакты и цены — **временные**, их нужно заменить на реальные.

## Технологии

| Что | Зачем |
| --- | --- |
| [Next.js](https://nextjs.org/) (App Router) | Каркас сайта. Собирается в обычные HTML-файлы |
| TypeScript (строгий режим) | Проверяет, что данные заполнены правильно |
| Tailwind CSS | Оформление |
| ESLint | Поиск ошибок в коде |
| GitHub Actions + GitHub Pages | Автоматическая проверка и бесплатная публикация |

Сервера, базы данных и платных сервисов нет.

## Как устроены папки

```
src/
  app/                  страницы сайта
    page.tsx            главная страница (порядок секций)
    catalog/page.tsx    каталог: все категории (/catalog/)
    catalog/[category]/ страница категории (/catalog/excavators/ и др.)
    catalog/[category]/[id]/ страница машины (/catalog/excavators/excavator-crawler-22t/)
    ui/page.tsx         служебная страница дизайн-системы (/ui)
    not-found.tsx       страница ошибки 404
    layout.tsx          общий каркас: шрифт, шапка, подвал, заголовок вкладки
    globals.css         дизайн-система: цвета, размеры текста, радиусы
  components/
    ui/                 базовые компоненты: кнопки, метки, карточки, поля
    layout/             шапка, подвал, логотип
    sections/           секции главной страницы
    catalog/            сетка категорий и таблица сравнения для каталога
  content/              ВРЕМЕННЫЕ ДАННЫЕ — тексты, контакты, техника, цены
  types/                описание структуры данных
  lib/                  вспомогательные функции
public/
  placeholders/         SVG-заглушки вместо фотографий техники
.github/workflows/      автоматическая проверка и публикация
CLAUDE.md               правила проекта для следующих заданий
```

## Где что менять

Все файлы можно редактировать прямо на сайте GitHub: откройте файл → значок карандаша ✏️ → внесите изменения → **Commit changes**.
Лучше делать это в отдельной ветке и через Pull Request (см. ниже).

| Что изменить | Файл |
| --- | --- |
| Название компании, слоган, описание | `src/content/site.ts` → `name`, `tagline`, `description` |
| Телефон, email, адрес, график | `src/content/site.ts` → `contacts` |
| Города и районы | `src/content/site.ts` → `cities` |
| Преимущества, шаги работы, вопросы и ответы | `src/content/site.ts` → `advantages`, `workSteps`, `faq` |
| Пункты меню | `src/content/site.ts` → `navigation` |
| Заголовки и тексты секций главной | `src/content/home.ts` |
| Заголовки страниц каталога | `src/content/catalog.ts` |
| Категории техники | `src/content/equipment.ts` → `categories` |
| Подробное описание категории, «Для каких работ», «Что уточнить при заявке» | `src/content/equipment.ts` → `intro`, `applications`, `requestChecklist` у категории |
| Техника, характеристики, цены, минимальный срок | `src/content/equipment.ts` → `equipment` |
| Описание машины на её странице | `src/content/equipment.ts` → поле `description` у машины (если не заполнено — берётся описание категории) |
| Условия аренды и подписи на странице машины | `src/content/catalog.ts` → `equipment` |
| Какая техника показана в «Популярной технике» | `src/content/equipment.ts` → `featured: true` |
| Цвета и шрифтовые размеры | `src/app/globals.css` → блок `@theme` |

**Телефон** указывается дважды: `phone` — как его видит посетитель (`+7 (861) 123-45-67`),
`phoneHref` — для кнопки «Позвонить», только `+` и цифры (`+78611234567`).

**Новая машина:** добавьте запись в `equipment` с уникальным `id` латиницей — её страница
`/catalog/<категория>/<id>/` появится автоматически. Не меняйте `id` у опубликованной машины: изменится адрес страницы.

**Новая категория:** добавьте её идентификатор (латиницей, например `"cranes-tower"`) в тип `CategoryId`
в `src/types/equipment.ts` и запись в `categories` в `src/content/equipment.ts`. Страница
`/catalog/<идентификатор>/` появится автоматически при следующей сборке.

**Цена** пишется числом без пробелов: `pricePerShift: 25000` → на сайте «от 25 000 ₽ / смена».

> ⚠️ Всё из папки `src/content/` видно любому посетителю сайта.
> Никогда не записывайте туда закупочные цены, данные поставщиков, пароли и токены.

### Как заменить изображения

1. Загрузите фотографию в папку `public/` (например, `public/equipment/excavator-01.jpg`):
   на GitHub откройте папку → **Add file** → **Upload files**.
2. В `src/content/equipment.ts` у нужной машины замените поле `image`:
   `image: "/equipment/excavator-01.jpg"` (путь начинается с `/`, слово `public` не пишется).
3. Обновите `imageAlt` — короткое описание фото для незрячих пользователей.

Рекомендуемый формат фото — горизонтальный 4:3 (например, 1600×1200), JPG или WebP до 300 КБ.

## Запуск на компьютере (необязательно)

Нужен [Node.js](https://nodejs.org/) версии 20.9 или новее.

```bash
npm install        # один раз — установить зависимости
npm run dev        # запустить сайт: http://localhost:3000
```

На iPad локальный запуск не нужен: проверяйте сайт по ссылке GitHub Pages после публикации.

## Проверки

```bash
npm run lint       # ESLint — ошибки в коде
npm run typecheck  # TypeScript — правильность типов и данных
npm run build      # production-сборка, готовый сайт появится в папке out/
npm run check      # все три проверки подряд
```

Эти же проверки автоматически запускаются на GitHub для каждого Pull Request
(вкладка **Actions** или блок проверок внизу страницы Pull Request).
Зелёная галочка ✅ — всё хорошо, красный крестик ❌ — есть ошибка, открывайте подробности.

## Ветки и Pull Request

- `main` — опубликованная версия сайта. Напрямую в неё не пишем.
- Каждое задание — отдельная ветка, например `feature/01-foundation-homepage`.
- Изменения попадают в `main` через **Pull Request** (запрос на слияние).

Как открыть Pull Request с iPad:
1. Откройте репозиторий на github.com в Safari.
2. Вкладка **Pull requests** → **New pull request**.
3. `base: main`, `compare:` — ваша ветка → **Create pull request**.
4. Дождитесь зелёной галочки проверок → **Merge pull request** → **Confirm merge**.

## Публикация на GitHub Pages

После слияния Pull Request в `main` автоматически запускается workflow
**«Публикация на GitHub Pages»** (`.github/workflows/deploy.yml`): он проверяет код,
собирает сайт и публикует его.

### Однократная настройка (нужно сделать один раз)

1. Репозиторий → **Settings** → **Pages**.
2. В разделе **Build and deployment** → **Source** выберите **GitHub Actions**.
3. Репозиторий → **Settings** → **Actions** → **General**:
   - **Actions permissions** — должно быть разрешено запускать actions
     (например, «Allow all actions and reusable workflows»);
   - **Workflow permissions** можно оставить «Read repository contents…» —
     нужные права (`pages: write`, `id-token: write`) прописаны в самом workflow.
4. Если репозиторий приватный, GitHub Pages доступен только на платных тарифах GitHub.
   Для бесплатного аккаунта репозиторий должен быть публичным.

Адрес сайта: `https://<владелец>.github.io/<имя-репозитория>/`.
Для этого репозитория: **https://tsum323.github.io/TEHNIKA/**.
Точный адрес также показан в **Settings → Pages** после первой публикации.

Сайт работает в подпапке (`/TEHNIKA/`), поэтому при сборке в GitHub Actions
передаётся переменная `NEXT_PUBLIC_BASE_PATH`. Если репозиторий переименовать,
ничего менять не нужно — путь определяется автоматически.

Опубликовать вручную: **Actions** → **Публикация на GitHub Pages** → **Run workflow**.

## Страницы

| Адрес | Что это |
| --- | --- |
| `/` | Главная страница — краткий обзор техники |
| `/catalog/` | Каталог: все категории |
| `/catalog/excavators/` и т. д. | Страница категории: описание, модели, сравнение характеристик, подсказки для заявки |
| `/catalog/excavators/excavator-crawler-22t/` и т. д. | Страница машины: фото, цена, все характеристики, условия аренды, другие модели категории |
| `/ui/` | Служебная страница дизайн-системы. Не индексируется поисковиками, в меню её нет |
| любой несуществующий адрес | Страница 404 |

## Что пока не реализовано

- Форма заявки с отправкой данных (сейчас — звонок или почта).
- База данных, серверная часть, авторизация, CRM, административная панель.
- Юридические страницы (политика конфиденциальности, оферта) — будут добавлены, когда появятся реальные документы.
- Аналитика и интеграции (Telegram и т. п.).
- Реальные фотографии, контакты, цены и название компании.
